# こども向けお絵描きアプリ 仕様書 v1.1

作成日：2026年10月25日  
更新日：2026年10月25日（v1.1：実機での試用を受けた変更。末尾の「14. 改訂履歴」を参照）  
対象：Claude Design / Claude Code  
開発対象：iPad Pro 9.7インチ（2016年モデル）

---

## 1. プロジェクト概要

### 1.1 目的

2歳児がiPad上で自由にお絵描きを楽しめる、シンプルなアプリケーションを制作する。

最初はペン、消しゴム、カラーパレットのみを備えたお絵描きアプリとする。

将来的には、描いた絵のピクセルを利用して、虫が色を運んだり、風で絵が飛んでいったりするインタラクティブな遊びへ発展させる。

### 1.2 コンセプト

**「指でぐりぐり描く。それだけで楽しい。」**

子どもが説明なしで使え、触った瞬間に色が現れることを重視する。

一般的なペイントアプリのような高機能性や正確な描画よりも、自由に描く気持ちよさを優先する。

### 1.3 設計原則

1. 描画時の操作感を最優先する。
2. 2歳児が文字を読まずに操作できる。
3. 画面構成と機能を最小限にする。
4. 誤操作が起きても困らない。
5. 古いiPadでも快適に動作する。
6. 将来のインタラクションを追加しやすい構造にする。
7. 描画内容はラスタ画像として管理する。

## 3. 初期版の機能

### 3.1 画面構成

画面は次の2領域で構成する。

**キャンバス**

- 画面の大部分を占める。
- 背景は白。
- 指で直接描画できる。
- 余計な装飾や文字を表示しない。

**ツールバー**

- 画面下部に配置する。
- 色パレットを表示する。
- ペンと消しゴムの切り替えを提供する。
- ボタンは2歳児が押しやすい大きさとする。
- 選択中の色・道具がわかるようにする。

画面全体はiPad横向き固定とする。

### 3.2 ペン

指でキャンバスをなぞることで描画する。

- タッチ開始位置に即座に色が現れる。
- 指の移動に合わせて連続的に描画する。
- 指を離すと描画が終了する。
- 線の端と角は丸くする。
- 入力座標間を補間して線の隙間を防ぐ。
- 描画済みの線を後から自動補正しない。
- 過度な平滑化や遅延処理を行わない。

ブラシの太さは初期値を設定し、実機で調整する。

### 3.3 ブラシの描き味

目標とする描き味は、クレヨンと油絵の具の中間。

- 太く描ける。
- 鮮やかな色が乗る。
- 指でぐりぐり塗るのが楽しい。
- 同じ場所を何度でも塗れる。
- 少し質感のあるブラシを将来的に実現する。

ただし、最初から複雑なブラシ表現は実装しない。

初期段階では、不透明な円形ブラシを採用する。

実機で描画の追従性を確認してから、クレヨン風のかすれ、エッジの質感、塗り重ねなどを追加・調整する。

筆圧対応は不要。

### 3.4 消しゴム

- 消しゴムボタンで切り替える。
- 指でなぞった部分を消去する。
- ペンより太い消去幅を使用する。
- 消去部分は透明ピクセルとする。
- 背景色を塗り重ねる方式にはしない。

消しゴムから色パレットを選ぶと、ペンモードに戻る。

### 3.5 色パレット

初期版では以下の7色を用意する。

| 色 | RGB（HEX） |
|---|---|
| 黒 | #212121 |
| 赤 | #F44336 |
| オレンジ | #FF9800 |
| 黄 | #FFEB3B |
| 緑 | #4CAF50 |
| 青 | #2196F3 |
| 紫 | #9C27B0 |

色を選択すると、その色で描画できる。

選択中の色は枠などで示す。

初期選択色は赤とする。

色数や配色は実機で使用しながら調整する。

## 4. 2歳児向けUI・操作仕様

### 4.1 基本方針

操作方法を説明しなくても使用できること。

- 文字による説明は不要。
- ボタンは大きくする。
- 操作対象を明確にする。
- キャンバスをできるだけ広くする。
- 子どもが誤って押しやすい位置に危険な操作を置かない。

### 4.2 タッチ操作

- 基本的に1本の指で描画する。
- 複数の指が触れた場合、最初の描画指だけを処理する。
- ツールバー上の操作は描画として扱わない。
- 描画途中に別の指で色を選んでも、現在の描画は同じ色で続ける。
- タッチがキャンバス外へ移動した場合は、描画をキャンバス内に制限する。

### 4.3 誤操作への対応

初期版では以下を通常UIに設けない。

- 全消去ボタン
- ファイル管理ボタン
- 設定画面
- 複雑なメニュー
- 文字入力
- 広告

全消去や作品管理は、将来、保護者向けの操作として追加することを検討する。

**v1.1での変更：** 実機で試した結果、上の子も含めて長く描くため、全部消しボタンをツールバーに追加した（4.4）。
消す前の絵は必ず写真アプリに保存されるので、誤って押しても作品は失われない。

### 4.4 全部消し

- ツールバーの右端、消しゴムから離れた位置に、ごみ箱の絵のボタンを置く。
- 押すと、消す直前の絵を写真アプリに保存してから（6.4）、キャンバスを消す。
- 消すときは、絵が小さな粒に分かれ、渦を巻きながらボタンへ吸い込まれる演出を出す（7.2）。

### 4.5 複数の指による誤操作

- 4本・5本指のスワイプやピンチによるアプリ切り替えは iPadOS の機能であり、アプリ側では止められない。
- 保護者向けに、次の設定を案内する。
  - アクセスガイド（設定 → アクセシビリティ → アクセスガイド）：アプリから出られなくなる。ホームボタンの3回押しで開始・終了する。
  - 設定 → ホーム画面とマルチタスク → ジェスチャ をオフ：指でのアプリ切り替えだけを止める。

## 5. 描画アーキテクチャ

### 5.1 ラスタ画像方式

描画データはRGBA画像として管理する。

ストローク単位のデータ管理は行わない。

具体的には、以下を保持しない。

- 描画済みストロークの座標列
- ストロークごとのID
- ストロークごとの色・太さ
- ベクター形式の描画データ

描画中は前回のタッチ座標など、一時的な入力状態を保持してよい。

### 5.2 レイヤー構成

描画構成は次のとおり。

- Background：白い背景
- PaintTexture：透明背景のRGBA画像
- Effects：将来追加するエフェクト表示領域
- UI：パレット・道具

白い背景と描画テクスチャは分離する。

透明なピクセルは描画が存在しない状態を意味する。

### 5.3 描画処理

UnityのRenderTextureへのGPU描画を第一候補とする。

処理の流れ：

1. タッチ座標を取得
2. キャンバス座標へ変換
3. 前回座標との間を補間
4. ブラシを描画
5. RenderTextureを更新
6. 画面に表示

タッチのたびにTexture2D.SetPixelを大量に実行する方式は避ける。

描画中にGPUからCPUへの同期読み戻しを行わない。

RenderTextureへの描画では、既存の描画内容を保持しつつ更新する。読み書きの競合が発生しないよう、必要に応じて一時RenderTextureを利用する。

### 5.4 キャンバス解像度

内部描画解像度は、表示解像度と分離する。

初期目安は1024×768程度を上限とし、実際のキャンバス領域の縦横比に合わせて決定する。

画面への表示時は適切に拡大する。

解像度は設定値として管理し、後から変更可能とする。

## 6. 保存・復元

### 6.1 自動保存

子どもに保存操作を要求しない。

- 描画内容を自動保存する。
- アプリ終了後も絵を保持する。
- 再起動時に前回の絵を復元する。
- 保存先はアプリ専用のローカル領域。
- ネットワーク接続不要。

保存形式はPNGとする。

透明部分を保持できるRGBA PNGとして保存する。

### 6.2 保存タイミング

描画中の性能を優先し、毎フレームの保存は行わない。

一定時間操作がない場合や、アプリがバックグラウンドに移行する際に保存する。

保存処理が描画を妨げないようにする。

保存中断に備えて、一時ファイルを利用するなど、安全な更新方法を採用する。

### 6.3 初期版の作品管理

初期版ではキャンバスを1枚だけ管理する。

複数作品の保存、一覧表示、画像共有などは将来対応とする。

### 6.4 全部消し時の写真保存（v1.1で追加）

- 全部消しの直前の絵を、白い背景と合成したPNGとして写真アプリに保存する。
- 何も描かれていないときは保存しない。
- 初回のみ、iPadOSが写真への追加の許可を求める。
- 将来は、並行して開発しているライフログアプリへ送れるようにすることを検討する（現時点では対応しない）。

## 7. 将来のインタラクション

### 7.1 基本思想

描いた絵をピクセルの集合として扱う。

絵の意味を認識することは必須としない。

描画内容のピクセルそのものを遊びの素材とする。

### 7.2 想定エフェクト

**虫が色を運ぶ**

- 虫が色付きピクセルに近づく。
- 一部のピクセルを取得する。
- 取得した部分はキャンバスから消える。
- 虫がピクセルを別の場所に運ぶ。
- 運んだピクセルを配置する。

**風で絵が飛ぶ**

- 風が吹く。
- 絵の一部が粒子になる。
- 粒子が風の方向に移動する。
- 絵が徐々に崩れていく。

**吸い込み（v1.1で実装済み）**

- 全部消しのときに、絵が小さな粒（4×4ピクセル）に分かれる。
- 粒は渦を巻きながら全部消しボタンへ吸い込まれる。ボタンに近い粒から先に動く。
- 描画テクスチャのコピーを使い、粒の動きは頂点シェーダーで計算する（CPU処理なし）。

その他、重力、振動、色の集合なども将来検討する。

### 7.3 エフェクト時の処理

通常描画中は、画像を通常のRGBAテクスチャとして管理する。

エフェクト実行時にのみ、必要なピクセルを抽出・加工する。

必ずしも1ピクセルを1粒子として扱う必要はない。

複数ピクセルをまとめて粒子化してもよい。

粒子化の単位や処理方式は、エフェクトごとに決定する。

### 7.4 アーキテクチャ上の条件

描画処理とエフェクト処理は分離する。

エフェクト側から描画テクスチャを参照・加工できるインターフェースを用意する。

ただし、初期版ではエフェクト自体は実装しない。

## 8. パフォーマンス要件

### 8.1 最優先事項

描画時の入力追従性を最優先する。

目標：

- 描画中60fps
- タッチ開始直後に描画結果を表示
- 長時間描いても性能が低下しない
- 指を高速に動かしても線が途切れない
- 描画中の不要なメモリ確保を避ける

60fpsが安定しない場合は、描画解像度やブラシ処理を優先的に見直す。

### 8.2 旧型iPadへの配慮

- RAM 2GBを前提とする。
- 高解像度テクスチャの多用を避ける。
- Compute Shaderへの依存を必須としない。
- 複雑なポストプロセスを使用しない。
- GPUとCPUの同期を最小化する。
- 必要以上のライブラリやパッケージを導入しない。

## 9. ソフトウェア構成

推奨する責務分離：

**InputController**

タッチ入力の取得と管理。

**BrushController**

ブラシの色・太さ・描画モードを管理。

**CanvasRenderer**

RenderTextureへの描画と画面表示。

**CanvasData**

描画テクスチャとキャンバスの状態を管理。

**EraserController**

透明ピクセルによる消去処理。

**DrawingPersistence**

PNG形式での保存・復元。

**DrawingUI**

パレット・ツールバーの表示と操作。

**EffectSystem（将来）**

ピクセルの取得・移動・再配置などを扱う。

各機能はできるだけ独立させ、UIデザインやブラシ実装を後から変更しやすい構造とする。
